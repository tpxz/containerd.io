---
title: 路线图
---

containerd 使用 issue 和 milestone 来定义其路线图。
`ROADMAP.md` 文件在开源项目中很常见，但我们发现它们很快就会过时。
我们选择基于 issue 和 milestone 的方式，这样 maintainer 和社区可以随着工作的新增与完成持续保持更新。

## Issue {#issues}

打上 `roadmap` 标签的 issue 是高层次的路线图条目。
它们是 containerd 社区希望完成的任务和/或功能。

更小的 issue 和 pull request 可以引用回打了标签的主路线图 issue，以便细化整体目标的推进情况。

## Milestone {#milestones}

Milestone 定义了某个 issue、pull request 和/或路线图条目应当在何时完成。
Issue 是「做什么」，milestone 是「什么时候做」。
开发过程很复杂，因此路线图条目可能会在不同 milestone 之间移动，取决于发布一项改动所需的剩余开发和测试工作。

## 搜索 {#searching}

要查找 containerd 当前计划中的路线图条目，可以按 `roadmap` 标签筛选。

[搜索路线图条目](https://github.com/containerd/containerd/issues?q=is%3Aopen+is%3Aissue+label%3Aroadmap)

搜索到路线图条目后，你可以查看它们被安排在哪个 milestone 中完成以及进展情况。

[查看 Milestone](https://github.com/containerd/containerd/milestones)
